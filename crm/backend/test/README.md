# Тесты CRM «Архидея»

Два независимых уровня. Первый гоняется всегда и везде, второй — когда нужно
проверить систему целиком.

## 1. Юнит-тесты — `npm test`

Покрывают чистую логику, на которой держатся деньги и разграничение доступа:

| Файл | Что проверяет |
|---|---|
| `src/common/permissions.spec.ts` | Матрица прав: что открыто менеджеру, что закрыто, как работают личные флаги |
| `src/orders/order-pricing.spec.ts` | Расчёт стоимости: объём × ставка, доп. услуги, скидка, защита от двойного начисления |
| `src/common/time/dushanbe.spec.ts` | Границы суток и периодов по Душанбе (UTC+5) |

Базы данных не требуют, идут за пару секунд:

```bash
npm test            # весь набор
npm run test:watch  # перезапуск при правках
npm run test:cov    # с покрытием
```

## 2. Сквозные проверки — `test/e2e/`

Гоняются по живому API и проверяют то, что юнит-тестами не поймать: реальные
коды ответов под каждой ролью и весь путь сделки от заявки до денег.

> **Только против локального сервера.** Скрипты создают клиентов, заказы,
> клинеров и бригады. Против боевой базы они откажутся запускаться — но
> не полагайтесь на это, а проверяйте `API_URL`.

### Подготовка

```bash
# 1. База (любой пустой Postgres)
#    DATABASE_URL=... в crm/backend/.env
npx prisma migrate deploy

# 2. Пароли тестовых сотрудников в .env — иначе войти не получится:
#    SEED_PW_ANISA=..., SEED_PW_MUSLIM=..., SEED_PW_MUNIM=...

# 3. Сервер
npm run build && node dist/main
```

### Запуск

```bash
npm run test:access     # матрица доступа: каждый эндпоинт под обеими ролями
npm run test:lifecycle  # весь путь сделки под менеджером
```

Переменные окружения (у всех есть значения по умолчанию):

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `API_URL` | `http://localhost:4000/api` | Адрес API |
| `INTAKE_KEY` | `local_test_intake_key` | Ключ приёма заявок (= `LEADS_INTAKE_API_KEY`) |
| `DIRECTOR_LOGIN` / `DIRECTOR_PASSWORD` | `anisa` / `testpass123` | Кабинет руководителя |
| `MANAGER_LOGIN` / `MANAGER_PASSWORD` | `muslim` / `testpass123` | Кабинет менеджера |

Менеджер по умолчанию — Муслим: он в отделе продаж, и авто-распределение
отдаёт заявки с сайта именно ему. Для другого сотрудника заявка не создастся
на его имя, и половина проверок пропустится.

Скрипт возвращает код `1`, если нашёл хотя бы одно расхождение — это удобно
для CI.
